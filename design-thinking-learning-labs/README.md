# Design Thinking Learning Lab — CLA 212

Six standalone, browser-based, unbranded learning simulations with a shared red-and-white/Georgia-and-Arial visual style. Each HTML file embeds its own CSS, JavaScript, and scenario data. No external APIs or login required.

## Student labs

1. [Interview Simulator](01_Interview_Simulator.html): Ask questions and collect evidence.
2. [Problem Framing](02_Problem_Framing.html): Analyze interview evidence and revise the problem.
3. [Idea Generation](03_Idea_Generation.html): Explore divergent creativity techniques.
4. [Idea Selection](04_Idea_Selection.html): Compare tradeoffs and justify a choice.
5. [Rapid Prototyping](05_Rapid_Prototyping.html): Arrange and preview a service journey.
6. [Test & Iterate](06_Test_and_Iterate.html): Simulate testing, improve, and retest.

Both scenarios are available throughout: **Jordan**, who considers campus events, and **Elena**, who navigates a customer pickup experience.

## Using the files in Canvas
Host this folder using GitHub Pages or another approved static host. Add a *direct link* to each standalone HTML file to the appropriate Canvas module; if using an iframe, give it an informative title and provide a direct-link alternative. Confirm Canvas download/import functionality with a student test account.

Students export interview evidence in JSON, import it into Problem Framing, then use progress JSON export/import to carry their work into subsequent modules. Each simulation also supports its own independent sample case. Student work stays in their browser unless they download and submit it.

## Accessibility and validation
See [Accessibility Report](Accessibility_Report.md). Keyboard controls, 320-pixel reflow, basic labeling, and scenario click-through were tested, but formal assistive-technology and Canvas acceptance testing remain outstanding.

Simulation user feedback is fictional; it is not a substitute for real research.
